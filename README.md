기초 학습 (6일)
모든 인원이 이 과제에 집중할 수 있을 시기까지 html/css/js에 대해서 각자 알아서 학습<br>
과제 pdf 분석 이전에 진짜 기본적인 영역부터 자습해서 자연스럽게 MPA 기준으로 학습함<br>

기획 (8일)
본격적으로 과제 pdf 분석<br>
요구 조건을 분석하며 SPA 구조 안에서 local로 돌아가는 pong game이 1vs1, 토너먼트를 제공해야하는 부분 확인<br>
프론트엔드는 3명이라 각자 라우터 및 여러 페이지 담당 / pong 게임 담당 / 추가 기능 담당으로 분리해서 진행.<br>
내가 pong 게임 담당을 맡아 게임 구현을 위해 분석하면서 과제에서 pong 게임을 위해 추가 가능한 모듈이 뭔지, 어떤걸 추가할건지 탐색하게 되었다.<br>

이미 뭘 해야하는지 정리를 끝낸 지금 시점에서 생각하면 당연히 pong 게임이면 탁자가 될 영역 안에 공과 채가 있고 탁자는 움직이지 않지만 공과 채는 위치와 벡터를 가지며 자연스럽게 좌표공간 안에서 탁구대의 테두리는 특정 값으로 설정 가능하니 계산을 편하게 진행하기 위해 탁구대의 정 중앙을 0, 0으로 하여 우상향 가능하게 정의해서 공과 채가 어떤 조건으로 움직이는지, 공이 테두리나 채에 맞는 판정은 어떻게 하는지 적고 프레임마다 벡터를 기반으로 위치를 옳겨주면 되는 간단한 프로그램인데 하나하나의 과정마다 정말 그렇게 하는것이 옳은지 고민해서 그런가 2주동안 계속 이것 저것 찾고 적용해보고 마음에 안들면 지우는 과정을 반복하다 나름 내가 내 코드를 재사용하기 좋게 분리해서 작성하여 local pong game을 먼저 완성했다.

작업 중 Three.JS를 활용한 웹 사이트 제작기에 대한 발표를 보게되었고 기존에 한 miniRT에서의 접근 방식과 동일하여 굉장히 익숙한 형태로 3차원 공간을 렌더링 할 수 있는 도구라는것을 알게되어 [Three.js doc](https://threejs.org/docs/)을 기반으로 빠르게 필요한 부분을 찾아 추가할 수 있었다.<br>
디자인적으로 정말 다양한 pong 게임이 있다는것은 [Ponggame](https://www.ponggame.org/)이라는 사이트를 통해 알고있었지만 3D 렌더링이긴 한데 원래의 pong 게임의 시야는 되도록 유지하고 실제 탁구장 색에 맞추어 진행하여 그렇게 티가 나지 않았던 것 같다.<br>
다만 방금 작성하다가 생각난건데 z값을 x축에 따라 변동시켜 2번 튀기게 보이는 구성도 좋았을 것 같다.

2D 로컬 퐁을 완성한 후 remote pong에 필요한 것이 뭔지 고민하면서 WebSocket이 필요하다는 사실을 알게되어 학습을 시작했다.<br>


로컬 퐁을 먼저 만들었다보니 ws를 활용하기 위해선 서버를 거쳐야했다.<br>
그래서 서버에서 검증을 해줘야할지, 한다면 어떻게 해야할지 고민해보여 여러가지를 고민해보게 되었다.<br>
만약 서버에서 돌린다면 파이썬으로 1초를 60번으로 나눠서 호출하는게 되겠고 js에서 돌린다면 request animation frame을 쓰면 될 것이었다.<br>
front에서 렌더링하고 서버는 사실상 event 전달만 해주는 구조가 훨씬 성능적으로 좋다는 점과 이 프로젝트는 딱히 돈 들여서 기록 남겨야하는 그런 종류의 게임이 아니라 지인끼리 혹은 랜덤으로 만난 사람끼리 즐겁게 하는게 목표라는점을 종합해서 서버에서의 검증이 없으면 조작에 취약하다는 사실을 알지만 그런 해킹을 방지하기 위해 전체적인 플레이 경험을 낮추는 것 보단 취약하더라도 더 원활한 게임이 깔끔하게 진행되는 것을 목표로 하기로 하여 클라이언트 중 왼쪽 플레이어 기준으로 렌더링하게 제작하기로 하였다.<br>
